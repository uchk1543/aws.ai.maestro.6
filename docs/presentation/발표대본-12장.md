# 발표 대본 (12장)

- 장 번호는 `발표자료-v2.html`과 같다. 5판(팀 피드백 반영): 이야기의 뼈대를 **분류 → 읽기 → 대조 → 다시 확인 → 정리**로 다시 세웠다.
- **핵심 한 문장**: 서류 네 장을 올리면 나누고, 읽고, 서로 맞춰 보고, 다시 확인한 뒤 정리한다. 읽기는 AI, 판정은 코드, 예외만 사람이다.
- 번호가 붙은 문장을 그대로 읽는다. 장마다 '화면' 줄에 언제 →를 누르는지 적었다. 장표에서 `T`를 누르면 장마다 아래 초와 지난 시간이 뜬다.
- 측정 조건과 출처는 화면 맨 아래 한 줄과 부록에만 있다. 물으면 '조심'에 적힌 대로 답한다.
- 분량: 말 5:26 + 시연영상 1:38 = 7:04 (1초에 3.8음절 기준). 자세한 것은 맨 아래 '시간표'에 있다.

## 3장. 두 가지 오류 — 30초

**화면**: 2번에서 한 번(두 숫자에 빨간 테두리), 3번에서 한 번(오른쪽 HS 상자와 74%).

1. 서류에서 나는 오류는 두 가지입니다.
2. 첫째는 서류끼리 값이 다른 경우입니다. 같은 화물인데 총중량의 앞 두 자리가 바뀌었습니다.
3. 둘째는 품목분류, HS 코드가 틀린 경우입니다. 서류끼리 맞아도 생깁니다.
4. 관세청은 오류 신고의 74퍼센트가 품목분류 오류라고 밝혔습니다.

**조심**
- 74퍼센트는 '오류 신고 가운데 품목분류의 비중'이다. '신고의 74퍼센트가 오류'가 아니다.
- "한국 통관 서류의 몇 퍼센트가 틀린다"고 말하지 않는다.
- 첫째는 대조 규칙이 잡고, 둘째는 HS 추천과 사람 확정으로 다룬다. 서류끼리 같은 틀린 HS가 적힌 경우는 대조로 못 잡는다(심은 7건 중 5건).

## 4장. 해결 — 40초

**화면**: 다섯 단계는 처음부터 보인다. 4번에서 한 번(갈림 두 상자), 5번에서 한 번(맨 아래 세 마디). 끝나면 다음 장에서 Enter로 영상을 튼다.

2. AI가 서류를 나누고 읽으면, 코드가 규칙 13개로 서로 맞춰 봅니다.
3. 어긋난 칸은 다른 방법으로 다시 확인하고, HS 코드와 신고서 초안까지 정리합니다.
4. 문제가 없으면 바로 등록하고, 나머지는 근거를 붙여 사람에게 넘깁니다.
5. 읽기는 AI, 판정은 코드, 예외만 사람입니다. 영상으로 보시겠습니다.

**조심**
- "전부 자동"이라고 말하지 않는다. HS 확정과 승인은 사람이 한다. 4번의 '문제가 없으면'은 화면에 적힌 대로 '불일치·확인 필요가 없고 HS가 모두 확정된 건'이다(8장에서 다시 말한다).
- 초안은 수입신고서 초안이다. 실제 세관 신고는 하지 않는다. 등록은 가상 WMS다.
- 규칙 13개는 배포본 기준이다(대조 규칙표 `tools/rules/rules.csv`).

**→ 여기서 시연영상 약 1분 38초** (`시연영상.mp4`, 최종본). 부산항 여는 장면 뒤에 네 장면이다: 올리면 읽고 대조, 틀린 칸 → HS 선택 → 신고서 초안, 대시보드, 말로 묻는 현황.

## 5장. 화면 — 24초

**화면**: 3번에서 한 번(02 서류끼리 대조), 4번에서 한 번(03 다시 확인, 노란 글씨).

**조심**

## 6장. 설계 — 47초

**화면**: 세 상자는 처음부터 보인다. 4번에서 한 번(순서를 바꾼 결과 두 상자), 5번에서 한 번(46건 가운데 41건).

1. 설계의 핵심입니다. 읽기는 AI가, 판정은 코드가 합니다.
2. 비전 모델은 양식마다 규칙을 짜지 않아도 읽습니다.
3. 판정을 코드가 하면 같은 서류에 늘 같은 결과가 나오고, 규칙마다 출처가 남습니다.
4. 순서를 바꿔서도 재 봤습니다. OCR로 먼저 읽으면 양식마다 규칙을 짜야 했고, 모델에 판정까지 맡기면 정상 서류 4세트를 오류로 봤습니다.
5. 그래서 OCR은 두 번째 근거로 씁니다. 짚은 46건 가운데 41건을 이렇게 다시 확인했습니다.

**조심**
- "비전 모델이 OCR보다 정확하다"고 말하지 않는다. Textract도 좌표 규칙을 짜면 72칸 중 71칸을 읽었다. 다만 우리 양식 전용이었다.
- "모델에 맡기면 흔들린다"고 말하지 않는다. 모델 혼자도 심은 오류 37건은 모두 찾았다.
- 46건은 개발용 75세트에서 짚은 건수(불일치 43, 확인 필요 3)다. 다시 확인 근거는 Textract 24, PDF 글자 17, 모델 다시 읽기 2, 없음 3이다.
- 양식은 8가지로만 쟀다.

## 7장. 규칙에 따라 정리 — 34초

**화면**: 왼쪽 HS 화면은 처음부터 보인다. 3번에서 한 번(신고서 초안), 4번에서 한 번(초록 상자: WMS 자동 등록 조건).

1. 맞춰 본 값은 규칙에 따라 정리합니다.
2. HS 코드는 AI가 후보와 이유를 내고, 사람이 확정합니다. 한 번 확정한 품목은 다음부터 자동입니다.
3. 신고서 초안은 코드가 채우고, 칸마다 어느 서류에서 왔는지 남깁니다. 문제가 남은 칸은 비워 둡니다.
4. WMS 자동 등록은, 문제가 없고 HS가 확정된 건만 합니다.

**조심**

**화면**: 3번에서 한 번(큰 숫자 셋), 4번 뒤에 한 번(아래 숫자 넷: 분류, 읽기, HS 후보, 현황 질문. 읽지 않고 가리키기만 한다).

3. 심은 오류 37건을 모두 찾았고, 정상 서류를 오류로 본 것은 없었습니다.

- "시간 단축 몇 퍼센트"를 말하지 않는다. 사람이 처리하는 시간은 재지 않았다.

## 10장. 아키텍처 — 32초

**화면**: 그림 한 장이다. 누를 것 없음. 왼쪽(올리기) → 가운데(AI가 읽기, 코드가 판정) → 오른쪽(결과) 순서로 가리킨다.

1. 구조는 서버리스입니다. 바로 답하는 Lambda와 오래 처리하는 Lambda를 나눴습니다.
2. 처리 Lambda 안에서 Strands Agent가 도구 6개를 골라 부릅니다.
3. Bedrock의 모델은 읽기와 HS 후보에 쓰고, Textract는 다시 확인하는 두 번째 근거로 씁니다.
4. 판정과 신고서, 등록에는 모델을 쓰지 않습니다.

**조심**
- "모두 서울에서 처리한다"고 말하지 않는다. 모델 추론은 global 프로필이라 국외에서 처리될 수 있다. 서울에서 직접 부를 수 있는 모델로 분류와 읽기 15장을 다시 쟀고 결과가 같았다. 지금 배포는 Sonnet 5.5(global)이고 PM이 유지하기로 정했다. 바꾸려면 환경 변수, 권한 정책, 배포 스크립트 세 곳을 고친다.
- "실시간"이라고 말하지 않는다. Lambda를 나눈 까닭은 API Gateway가 30초 안에 답해야 해서다.
- Guardrails는 채팅 입력의 프롬프트 공격과 유해 표현을 막는다. 무관한 질문은 코드가 막는다.

- 도구 여섯 개: `classify_document`, `read_document`, `cross_check`, `reread_field`, `recommend_hs`, `finish_report`. 한도는 모델 호출 12번, 150초이고 넘으면 코드가 고정 순서로 마저 한다. 끝났는지는 코드가 검사한다.

## 11장. 비용 — 28초

**화면**: 0.18달러는 처음부터 보인다. 2번에서 한 번(불일치를 놓치면), 3번에서 한 번(HS 오류를 놓치면), 4번에서 한 번(노란 띠).

1. 화물 한 건을 끝까지 처리하는 데 약 0.18달러, 250원쯤 듭니다.
2. 불일치를 놓치면 B/L 정정 한 번에 6만 원, 적재화물목록 과태료는 최대 100만 원입니다.
3. HS 오류를 놓치면 몇 년 뒤 추징으로 돌아옵니다.
4. 240건 가운데 한 건만 막아도 본전입니다.

**조심**
- 0.18달러는 개발용 75세트를 고정 순서로 한 번 돌린 평균이다. 토큰과 쪽 수는 실측이고 금액은 직접 요금으로 어림했다. 250원은 1달러 1,400원으로 바꾼 값이다.
- 6만 원, 최대 100만 원, 7.5억 원은 팀원이 준 그림의 값이다. 근거표에 출처가 없다. 발표 전에 출처를 확인하고, 확인 못 한 값은 말하지 않는다.
- "우리가 이 오류를 모두 막는다"고 말하지 않는다. 같은 틀린 HS가 두 서류에 적힌 경우는 대조로 못 잡는다. HS는 추천하고 사람이 확정한다.
- 배포본에서 한 건은 30초 안팎이다(D003 29.8초, D005 25.3초).
- 과제 기능 다섯 개 대조표는 부록 2에 있다. 물으면 그 장을 띄운다.
