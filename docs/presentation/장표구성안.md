**팀원 의견에서 고쳐 쓴 곳 (사실과 달라서)**
- "콘솔에서 정책을 정의" → 가드레일은 설정 파일(`infra/guardrail-chat.json`)과 스크립트로 정의한다. 막는 것은 프롬프트 공격과 유해 표현이다. 무관한 질문은 가드레일이 아니라 코드가 막는다 (#151, #205).
- 처리 Lambda의 "Bedrock 검증 → Textract 검증 → 서버 로직 검증" → 실제 순서는 **Bedrock 읽기 → 코드 규칙 판정 → Textract 다시 확인**이다. Bedrock은 검증하지 않고 읽기만 한다. 8장과 맞췄다.
- "Bedrock으로 쿼리로 바꿔 DB 조회" → 모델은 조회 조건만 만들고 조회는 코드가 한다. SQL을 만들게 하지 않는다.
- SNS는 저장소에 없다. 장표에 넣지 않았다.
- "배포 과정에서 Kiro를 썼다"는 저장소에서 확인하지 못했다. 장표에는 확인되는 것만 썼다: 규칙 문서 2개(`.kiro/steering`), Spec 폴더 5개, 이슈 하나 = PR 하나.
