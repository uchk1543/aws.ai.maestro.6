# Requirements Document

## Introduction

HS를 서류에서 확정하지 못한 품목('사람 확인 필요')은 지금 화면에서 사람이 후보에서 고를 수만 있고, 관세사에게 보낼 문서에는 나오지 않는다.
불일치 통지 문서(C7 #158, `notice_document`)는 문제 목록만 받고 HS 결과는 받지 않는다. 관세사가 분류하려면 서류 값과 후보뿐 아니라
제품 정보(재질·용도·구성품·사양서·사진)가 필요하다. 서류에서는 이 정보를 읽지 못하므로, "HS가 없다"만 알리면 관세사가 화주에게 다시 물어야 한다.
이번 일은 HS 미확정 품목을 담은 **HS 확인 요청서(PDF)** 를 만들어 내려받게 하는 것이다. 이슈: #260

정한 방향 (검수 완료서 X1 #258과 같은 방식):
- 새 의존성이 없다. `reportlab`과 `tools/fonts/`의 나눔고딕을 쓴다.
- 문서 내용은 코드가 저장된 결과에서 옮긴다. 모델을 부르지 않는다. 도구 결과에 없는 내용은 쓰지 않는다.
- HS는 AI가 확정하지 않는다 (agent-design.md 6번). 문서의 후보는 참고이고 최종 분류는 관세사가 한다.
- 파일을 저장하지 않는다. `GET`할 때 저장된 작업에서 만든다. 새 AWS 리소스·정책 변경이 없다.
- 2번 소유인 `tools/validate.py`의 `notice_document`는 고치지 않는다. 새 파일 `tools/hs_request.py`로 만든다.

참고한 실무 내용 (관세사 실무 글 정리, 사무소마다 다를 수 있음): 법정 보고는 세관으로 가고 관세사 연락은 메일·팩스·전화로 따로 한다. 식별 번호는 B/L 번호와 송장 번호,
서류끼리 비교한 값, 분류에 필요한 제품 정보(재질, 용도, 기능, 형상, 구성품과 수량, 사양서와 사진, 성분)를 함께 보낸다. 이 문서는 보내기 전에 사람이 검토한다.

담당: PM. `api/handler.py`는 4번, `web/`은 3번 리뷰를 받는다.

## Glossary

- **미확정 품목**: 품목별 HS 결과의 상태가 '사람 확인 필요'인 행.
- **서류 HS**: 서류에 적힌 HS를 적힌 그대로 (예 `9401.61`).
- **제품 정보 요청 목록**: 서류에서 읽지 못해 화주에게 받아야 하는 정보 (재질, 용도·기능, 형상, 구성품과 수량, 사양서·사진, 성분).

## Requirements

### Requirement 1: 요청서 내용

#### Acceptance Criteria

1. THE 요청서 SHALL 맨 위에 "자동 생성 문서, 사람이 검토한 뒤 전달, 후보는 참고이고 최종 품목분류는 관세사"를 적는다.
2. THE 요청서 SHALL 식별 정보를 담는다: 작업 번호, B/L 번호, 송장 번호, 수입자, 수출자, 원산지, 거래 조건, 만든 시각(한국 시간). 없는 값은 '없음'으로 적는다.
3. THE 요청서 SHALL 미확정 품목마다 행 번호와 품명, 서류별 값(서류 종류, 서류 HS, 수량, 총중량, 순중량, 금액)을 표로 담는다. 확정된 품목은 담지 않는다.
4. THE 요청서 SHALL 품목마다 후보 HS(최대 3개)를 `1234.56-7890` 모양으로, HS 표의 품목명과 근거(서류의 어느 칸)와 함께 담는다. 후보가 없으면 '없음'으로 적는다.
5. THE 요청서 SHALL 품목마다 자동 확정하지 못한 이유를 저장된 값으로 판단되는 사실만 적는다: 후보 없음, 서류에 HS 없음, 서류끼리 HS가 다름, 서류 HS가 10자리가 아님, 서류 HS 앞 6자리와 1순위 후보가 다름. 어느 것에도 해당하지 않으면 일반 문장을 적는다.
6. THE 요청서 SHALL 끝에 화주에게 받을 제품 정보 요청 목록과 "서류에서 읽지 못한 정보, 분류가 어려우면 관세사가 품목분류 사전심사를 신청할 수 있다"를 적는다.
7. THE 서류에서 읽은 글자 SHALL 데이터로만 넣는다 (표시 문법·지시문은 해석하지 않는다).
8. THE 문서 SHALL 한국어이고 한글이 깨지지 않는다.

### Requirement 2: 내려받기 API

#### Acceptance Criteria

1. THE API SHALL `GET /api/jobs/{job_id}/hs-request`로 PDF를 돌려준다 (`application/pdf`, 파일 이름 `hs-request-{job_id}.pdf`로 내려받기).
2. IF 작업이 없으면 THEN 404, 사람이 확인해야 하는 HS 품목이 없으면(확정됨, 처리 전) THEN 409와 이유를 JSON으로 돌려준다.
3. THE 만들기 SHALL 모델·AWS(S3, Bedrock)를 부르지 않는다. 서류 기록이 없어도 작업 결과의 품명·서류 HS·후보로 만든다.
4. IF PDF를 만들다 실패하면 THEN 500과 짧은 이유를 돌려주고 작업은 바뀌지 않는다.

### Requirement 3: 화면 링크

#### Acceptance Criteria

1. WHEN 미확정 품목이 있으면 THE 화면 SHALL HS 패널에 "HS 확인 요청서 받기" 링크와 품목 수를 보인다.
2. WHEN 미확정 품목이 없으면 THE 화면 SHALL 링크를 숨긴다.

## 범위 밖

메일·팩스 발송, 사전심사 신청서 양식, 화물관리번호(서류에 찍히지 않아 읽지 못함), 불일치 통지 문서와 합치기, 세관 이상보고서.
