# 끝까지 가는 작업 지도 (역할 분담 회의용 초안)

PM이 만든 회의 자료다. Spec이 아니다. 각 담당은 이 표에서 자기 몫을 골라 자기 Spec 폴더(.kiro/specs/NN-기능/)를 만든다.
"제안 담당"은 TEAM.md 1번 표의 담당(1 판독 · 2 검증 · 3 화면 · 4 서버 · 5 발표)을 따른 제안이고, 회의에서 바꿔도 된다.
근거: agent-design.md(규칙 번호), docs/schema.md(약속 번호).

## 1. 한 건이 끝까지 가는 흐름

```
[데이터셋]  서류 제작 · 정답지 · 가상 화물 기록
     │
[화면] 업로드 ──▶ [API] 업로드 URL ──▶ S3
     │                                  │
     └──▶ [API] 작업 생성 ──▶ [문서 처리 Agent]
                                 ├ 분류 → 읽기(+OCR) → 대조 → 다시 확인
                                 ├ HS 추천·확정
                                 ├ 신고서 초안
                                 └ 리포트 조건 검사 → 작업 저장 → 화물 기록
                                                       │
                                     조건 충족 → [가상 WMS] 자동 등록
                                     예외     → [화면] 사람이 HS 선택·승인
[화면] 진행·결과 ◀── [API] 작업 조회 (2초마다)
[화면] 현황 채팅 ──▶ [현황 조회 Agent] ──▶ 화물 기록 조회·집계
[평가] 정답지로 채점 ──▶ [발표] 숫자 · 시나리오 · 영상 · PDF
```

## 3. 먼저 끝나야 하는 것 (의존)
- **형식 약속**(tools/models.py, docs/schema.md)이 거의 모든 작업의 출발점이다. 바꾸면 화면·규칙·채점이 같이 바뀐다.
- **A1 서류**가 있어야 B2 실측, B5 규칙 고르기, H1 채점이 의미가 있다. 서류가 늦으면 전체가 늦는다.
- **F1 배포**가 있어야 화면이 실제 API에 붙는다. 그 전에는 예시 JSON으로 만든다.
- **A6 HS 표**가 있어야 C1·C2를 시작한다.
- **E1 통관 지연 기준**과 **A5 시드**가 있어야 E4·E5 결과가 의미가 있다.
- **H1 채점**이 있어야 발표 숫자(I2)가 나온다.

가장 긴 줄: A1 서류 → B1·B2 분류와 읽기 → B5·B7 대조 → B9 Agent 루프 → C1·C2 HS → C5 신고서 → D2 자동 등록 → H1 채점 → I2 숫자.

## 5. 사람별 분배

사람별 하는 일, 이슈 순서, 주고받는 것은 [TEAM.md](../../../TEAM.md)에 있다. 이슈는 `.github/tasks.csv`에서 만든다.

코드는 함수 모양과 데이터 모양까지 만들어 두었고, 몸통은 비어 있다(`NotImplementedError`).
각자 자기 파일의 몸통을 채우고, 남의 것을 기다릴 때는 `tests/unit/fakes.py`와 `docs/examples/`로 먼저 만든다.
