# 화면 디자인 명세

이 문서는 `web/src/styles.css` 와 컴포넌트가 따르는 기준이다. CSS 를 고치기 전에 여기를 먼저 고친다. 담당: 3번 화면.

## 1. 이 화면은 무엇을 하나

통관 담당자가 서류 4종(상업송장·포장명세서·선하증권·원산지증명서)을 올리면 AI 가 읽고, 코드가 대조해서 **사람이 볼 예외만** 넘긴다.
그래서 화면의 일은 둘이다.

1. **지금 할 일 하나를 바로 보이게** 한다. 문제없는 건은 사람이 볼 것이 없다.
2. **근거를 바로 확인하게** 한다. 불일치마다 어느 서류의 어느 칸인지, 적힌 값이 무엇인지 보인다.

### 원칙

1. **할 일이 먼저, 기록은 나중.** 작업 화면은 맨 위 '다음 할 일' 한 줄과 할 일이 있는 단계를 먼저 연다. 처리 과정 기록은 접어 둔다.
2. **색은 뜻이 있을 때만.** 파랑은 누를 것·고른 것, 빨강은 불일치·실패·오류. 그 밖은 회색 단계로만 구분한다.
3. **화면은 다시 세지 않는다.** 건수·상태·문장은 서버가 정한 값을 그대로 보인다 (docs/schema.md).
4. **서류 글자는 데이터다.** 서류에서 온 글자는 꾸미지 않고 그대로, 넘치면 줄을 바꿔 보인다.

## 2. 색

### 출처

회색 단계와 파랑 값은 **Toss 공개 화면 디자인 명세(2026-09 관찰값)** 에서 빌렸다. 우리 화면은 Toss 서비스가 아니므로 로고·이름·글꼴(Toss Product Sans)은 쓰지 않고 색 값만 쓴다.

| 우리 토큰 | 값 | 빌려 온 값 | 흰 바탕 대비 | 쓰는 곳 |
|---|---|---|---|---|
| `--ink` | `#191f28` | foreground-strong | 16.6:1 | 제목, 본문, 읽은 값 |
| `--ink-secondary` | `#4e5968` | foreground-secondary | 7.1:1 | 보조 글자, 표 머리 |
| `--muted` | `#6b7684` | muted | 4.6:1 | 힌트, 출처, 단계 설명 |
| `--faint` | `#8b95a1` | (우리 값) | 3.0:1 | 입력칸 안내문, 장식, 꺼진 표시. **글자로 쓰지 않는다** |
| `--primary` | `#0064ff` | brand (Toss Blue) | 4.9:1 | 채운 버튼, 고른 칩·탭·후보 바탕 (흰 글자) |
| `--primary-strong` | `#0050cc` | (우리 값) | 6.6:1 | 채운 버튼 누름 |
| `--primary-line` | `#3182f6` | primary | 3.7:1 | 테두리, 포커스 링, 그래프 막대. **흰 글자 바탕으로 쓰지 않는다** |
| `--primary-tint` | `#e8f3ff` | (우리 값) | – | 파랑 옅은 바탕 (안내 상자) |
| `--line` | `#e5e8eb` | hairline | – | 패널·목록 구분선 |
| `--border` | `#d1d6db` | border | – | 입력칸·표 테두리, 꺼진 토글 |
| `--fill` | `#f2f4f6` | surface-muted | – | 회색 칸, 표 머리, 고르지 않은 칩 |
| `--fill-2` | `#f9fafb` | (우리 값) | – | 더 옅은 바탕, 고르지 않은 단계 |
| `--bg` | `#ffffff` | canvas | – | 화면 바탕, 패널 |
| `--red` | `#d6402a` | (우리 값) | 4.5:1 | 불일치·실패·오류·통관 지연에만 |

- `#3182f6` 위에 흰 글자는 3.7:1 이라 본문 기준(4.5:1)에 모자란다. 그래서 채운 버튼은 `#0064ff` 를 쓴다.
- `--muted` 는 회색 칸(`--fill`) 위에서 4.2:1 이다. 회색 칸 위 13px 이하 글자는 `--ink-secondary` 를 쓴다.
- Toss 명세에는 오류·성공 색이 없다. 빨강은 우리 규칙(불일치·실패에만) 그대로이고, 성공은 색 대신 ✔ 표시와 글자로 보인다.
- 고른(파랑) 칸 위의 보조 글자는 회색 대신 `rgba(255,255,255,0.92)` 를 쓴다.

### 등급 색

| 등급 | 표시 |
|---|---|
| 불일치 | 빨강 바탕 흰 글자 배지, 빨간 왼쪽 줄 |
| 확인 필요 | 흰 바탕 빨강 테두리 배지 |
| 참고 | 회색 칸 배지, 회색 글자 |

### 그래프

한 색(파랑)의 짙기만 바꾼다: `#0064ff` → `#3182f6` → `#64a8ff` → `#90c2ff` → `#c9e2ff` → `#e8f3ff`. 그래프 아래에는 같은 값의 표를 늘 둔다.

## 3. 글자

- 글꼴: Pretendard. Toss Product Sans 는 따로 배포되지 않아 쓰지 않는다. 다른 글꼴을 Toss 글꼴이라고 부르지 않는다.
- 한글은 낱말 중간에서 줄을 바꾸지 않는다(`word-break: keep-all`). 번호·영문은 넘치면 끊는다.
- 크기는 앞머리 `typography` 의 7단계만 쓴다. 지금 CSS 에 있는 11px·16px·18px·22px·28px 은 다음 정리 때 가까운 단계로 옮긴다 (아래 '알려진 차이').
- 숫자(중량·금액)는 서류에 적힌 그대로 보인다. 화면이 단위를 바꾸거나 반올림하지 않는다.

## 4. 배치

- 모바일(767px 이하)을 기본으로 쓰고, 768px·1200px 에서 넓힌다. 양옆 여백은 22px, 가로 스크롤은 페이지에 생기지 않는다(넓은 표·단계 표시줄만 그 안에서 민다).
- 간격은 4·8·12·16·20·32px 만 쓴다.
- 메뉴: 모바일은 아래 탭(64px + 안전 영역), 태블릿·PC 는 위 왼쪽 칩.

### 작업 화면 (`#/jobs/{id}`)

위에서 아래로 이 순서다.

1. 제목 `작업 job-…` + 상태 배지 (+ 처리 중이면 경과 시간)
2. **다음 할 일** 한 줄 (서버 `next_action.message`) 과 그 단계로 가는 버튼
3. **단계 표시줄** 5칸: ① 처리 과정 ② 서류 대조 ③ HS 코드 ④ 신고서 초안 ⑤ WMS 등록
4. 고른 단계 하나의 내용

- 처음 열 때는 다음 할 일이 가리키는 단계를 연다: 불일치 → ② · HS 고르기 → ③ · 승인 → ⑤ · 처리 중 → ①.
- 결과가 나오기 전에는 ① 만 누를 수 있다.
- ① 처리 과정은 '서류 분류 / 서류 읽기 / 대조와 다시 확인 / HS 코드 / 마무리' 로 묶어 접는다. 실패가 있는 묶음만 펼친다.

### 화면 구성 (Toss 앱 구성 따름)

- **바탕은 회색(`--fill`), 내용은 흰 섹션 카드.** 카드는 20px 모서리, 테두리·그림자 없음, 안쪽 20px(모바일)·28px(태블릿·PC). 카드끼리는 바탕 회색으로 나뉜다.
- 흰 카드 안의 칸(입력칸, 회색 칸, 후보)은 `--fill`, 회색 바탕에 바로 놓이는 칸(종류 목록, 예시 질문, 단계 표시줄, 상태 배지)은 흰색.
- **위 막대(태블릿·PC)**: 흰 바탕 64px, 스크롤해도 붙어 있고, 아래 1px `--line`. 왼쪽 앱 이름 17px/700, 메뉴는 글자만 있고 고른 메뉴는 `--fill` 칸 + 굵게.
  모바일은 위 막대를 붙이지 않는다. 메뉴는 아래 고정 탭이고, 고른 탭은 진한 글자 + 파란 점이다.
  위 막대에 `backdrop-filter` 를 모바일에서 걸지 않는다 (안의 고정 탭이 막대 기준으로 붙는다).
- 모바일에서 아래 고정 버튼이나 입력칸이 있는 화면(업로드, AI chat)은 본문을 카드로 감싸지 않는다.

## 5. 모서리와 깊이

- 모서리: 배지 6px, 옅은 버튼·메뉴 10px, 단계·후보 칸 12px, 채운 버튼 16px, 섹션 카드 20px, 칩 999px.
- 그림자는 쓰지 않는다. 층은 바탕색(`--bg` / `--fill` / `--fill-2`)과 1px 선으로만 나눈다. 아래 시트(모바일 목록)만 예외로 옅은 그림자를 쓴다.
- 움직임은 0.15~0.2초 안에 끝낸다. 움직임 줄이기 설정이면 끈다.

## 6. 구성요소

| 이름 | 모양 | 상태 |
|---|---|---|
| 채운 버튼 `.primary` (화면마다 하나) | `--primary` 바탕, 흰 글자 17px/600, 16px 모서리, 높이 56px 이상 | 누름 `--primary-strong` + 0.98배, 꺼짐 투명도 0.45 |
| 옅은 파랑 버튼 `.next-go`, `.chat-new`, `.filter-clear` | `--primary-tint` 바탕, `--primary` 글자 14px/600, 10px 모서리, 높이 40px | 누름 `#d6e8ff`. 옅은 빨강 상자 안에서는 흰 바탕 |
| 글자 버튼 `button.link` | 바탕 없음, `--primary` 글자 | – |
| 칩·탭 `.kind`, `.doc-tab`, `.filter-chip` | 고르지 않음 `--fill` 바탕 `--ink-secondary` / 고름 `--primary` 바탕 흰 글자 | `aria-selected` 또는 `.active` |
| 단계 표시줄 `.stage` | 흰 칸, 테두리 없음, 12px 모서리. 고름은 2px `--ink` 안쪽 테두리 | 표시 원: 완료 ✔ `--primary`, 할 일 ! 빨강, 대기 … 회색, 실패 ✖ 빨강 |
| 섹션 카드 `.panel`, `.dash-panel`, `.doc-card` | 흰 바탕, 테두리 없음, 20px 모서리, 안쪽 20/28px | – |
| 다음 할 일 `.next-action` | 흰 카드, 문장 17px/700 `--ink`. 불일치·실패면 옅은 빨강(`#fdf0ee`) 바탕 | 버튼은 옅은 파랑 |
| 상태·등급 배지 `.status`, `.grade` | 테두리 없는 6px 칸, 13px/600. 기본 `--fill`, 끝남·문제 없음 옅은 파랑, 불일치·실패 빨강 바탕 흰 글자, 확인 필요 흰 바탕 빨강 테두리 | – |
| 표 (신고서 초안 등) | 머리 `--fill` 바탕 `--ink-secondary` 글자, 본문 흰 바탕 `--ink`, 1px `--line` 가로줄 | – |
| HS 후보 `.hs-candidate` | `--fill` 칸, 고르면 `--primary` 바탕 흰 글자 | 라디오 `accent-color: --primary` |
| 판독 오류로 넘기기 `.wms-override` | 빨강 테두리 옅은 빨강 바탕 상자, 체크 + 사유 입력 | 둘 다 채워야 승인 버튼이 켜진다 |

### 포커스

키보드로 온 칸에는 늘 보이는 링을 그린다: `outline: 2px solid var(--primary-line); outline-offset: 2px`.
Toss 공개 화면은 포커스 표시가 없는 곳이 많지만, 우리는 따르지 않는다.

## 7. 해야 할 것 / 하지 말 것

### 할 것
- 새 색이 필요하면 이 문서 표에 먼저 넣고 CSS 변수로 쓴다. CSS 에 16진 값을 바로 쓰지 않는다.
- 빨강을 쓸 때는 글자·표시(✖, !)를 함께 둔다. 색만으로 뜻을 전하지 않는다.
- 건수·문장은 서버 값을 그대로 쓴다.

### 하지 말 것
- Toss 로고·이름·글꼴을 쓰지 않는다. 빌린 것은 색 값뿐이다.
- `#3182f6` 위에 흰 글자를 올리지 않는다.
- 파랑을 장식에 쓰지 않는다 (누를 것·고른 것·그래프만).
- 그림자로 층을 만들지 않는다.

## 8. 알려진 차이 (다음 정리)

- 글자 크기 11·16·18·22·28px 이 남아 있다. 7단계로 모은다.
- 화면별 오래된 규칙의 모서리 14·18px 이 일부 남아 있다. 공통 틀은 `styles.css` 맨 끝 'Toss 화면 구성 층' 이 덮어쓴다. 다음 정리 때 화면별 규칙에 합친다.
- 대시보드 영상 위 글자(`rgba(255,255,255,…)`)와 영상 그림자(`rgba(0,0,0,…)`)는 토큰 밖이다.
- 포커스 링이 모든 구성요소에 있는지는 아직 다 확인하지 않았다.
- 어두운 화면(다크 모드)은 없다.
